# Contributing to leepr

## Prerequisites

- Node.js 20 or later (`node --version`)
- npm 10 or later

## Build and test

```bash
# Install dependencies
cd backend && npm install
cd ../frontend && npm install

# Run backend tests (must pass before any commit)
cd backend && npm test

# Type-check both packages
cd backend && npx tsc --noEmit
cd frontend && npx tsc --noEmit

# Build the frontend
cd frontend && npm run build
```

The backend test suite runs in a few seconds with no external services. The
watsonx tests mock the HTTP layer and run offline.

## Branch and pull-request convention

- One branch per feature or fix: `<type>/<short-description>`, e.g.
  `fix/nan-in-sensitivity`, `feat/add-latency-chart`.
- Open a pull request against `main`. The PR template provides a checklist;
  fill it in honestly.
- Squash-merge is preferred; keep the commit message in the format
  `<type>(<scope>): <subject>` (Conventional Commits).

## What is accepted

- Bug fixes with a test that reproduces the bug.
- New regions in `data/regions.json` with `source_url` and `last_verified` on
  every value. See the existing entries for the required fields.
- Frontend component improvements that stay within `docs/SCHEMA.md`.
- Documentation corrections.

Not accepted without prior discussion: new dependencies, schema changes, or
features not described in `docs/SCHEMA.md`. Open an issue first.

## AI-generated pull requests

AI-generated code is welcome. The bar is the same as for any other contribution:
the author must have run `npm test` and `npx tsc --noEmit` and must describe in
the PR body what they verified by hand (e.g. "ran the estimate endpoint against
the two example sites and checked the ranking output"). A PR that says only
"generated by X" with no human verification step will not be merged.

## Core rules (from AGENTS.md)

- The LLM layer never generates a number. All cost and financial math lives in
  `backend/src/engine/` as deterministic, tested TypeScript.
- `docs/SCHEMA.md` is the source of truth. Update it before changing the API
  shape or Zod schema.
- Every value added to `data/regions.json` needs `source_url`, `last_verified`,
  and `basis`.
